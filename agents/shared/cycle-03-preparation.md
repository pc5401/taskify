## 기존 계약으로 확정된 범위

- 생성: POST /columns/{columnId}/cards, 201 Card + ETag.
- 이동: POST /cards/{cardId}/move, 200 Card + ETag, If-Match 필수.
- Owner/Editor만 허용, Viewer와 비멤버는 거절한다.
- 목적지 컬럼 잠금 후 WIP 수·순서를 결정한다. 보드 전체 잠금으로 대체하지 않는다.
- 다른 보드의 컬럼·담당자·선행·태그 연결은 허용하지 않는다.
- 선행이 미완료여도 완료 컬럼 이동을 허용하고 승인된 warnings를 반환한다.
- 작성자는 인증 사용자이고 카드·태그 연결·활동 기록은 같은 트랜잭션에 둔다.

## 사용자 승인 정책

1. 생성은 끝에 추가, 이동은 beforeCard 앞 또는 끝. 간격 소진/Int32 범위 초과 시 목적지 컬럼을 1024 간격으로 정리하고 위치가 바뀐 카드 버전도 증가.
2. 같은 컬럼 재배치 허용, WIP에서는 자신 제외. 자기 앞 이동은 422, 결과 순서가 그대로면 버전·활동 기록 불변. 시작 자원 없음/접근 불가는 403, 권한 확인 뒤 잘못된 연결 대상은 422.
3. 새 태그 자동 생성, 대소문자 중복은 기존 태그 재사용 및 기존 표기 유지. 요청 중복 제거, 공백 원문 유지. 생성·이동 임시 UI 후 Figma 보정.

## 승인 후 작업 순서

QA가 인수 기준을 먼저 작성하고 승인 정책을 계약에 반영한다. BE API와 FE 생성 폼·이동 조작을 분리해 구현한다.
QA는 실제 DB/HTTP에서 동시 WIP 마지막 자리, 버전 충돌, 다른 보드 연결, Viewer 거절, 실패 후 행 불변을 검증한다.
생성의 선택 필드는 API 계약을 지원하되 미구현 멤버 검색 등을 임의로 추가하지 않는다.
브라우저 연결 가능 여부와 Figma 일치는 HTTP 검증과 구분한다. 해설 문서를 만든 뒤 통합한다.

## 작업 시작 당시 환경

API·Next·격리 PostgreSQL은 종료 상태이고 DB 데이터는 보존돼 있다. 검증 시 기존 클러스터를 start하며 init/reset하지 않는다.
main과 원격은 변경하지 않았다. 작업 브랜치는 codex/orchestration, 역할별 Git Worktree를 재사용한다.
