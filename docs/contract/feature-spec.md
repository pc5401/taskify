# Taskify 기능 명세서 v0.1

상태: 기획 초안. ChatGPT와 섹션 단위로 구체화한다.
범위: 코드잇 Taskify(대시보드 · 컬럼 · 카드 · 초대)를 기반으로, MVP를 넘긴 팀 일정 도구.
목적: 멀티 에이전트(FE / BE / QA)가 같은 계약을 보고 작업하게 한다. 화면 묘사보다 완료 조건이 우선이다.

한 줄 정의: 초대한 멤버만 들어오는 보드에서, 컬럼과 카드로 일을 옮기고, 누가 무엇을 막는지 기록이 남는다.

## 0. 이번 버전에서 하지 않는 것

- 결제, 조직 트리, SSO
- 모바일 네이티브 앱
- 실시간 공동 커서
- 다크모드, 랜딩 마케팅 페이지의 미세 인터랙션
- AI가 카드를 대신 작성하는 기능. 에이전트 실습 대상은 제품 안의 AI가 아니다.

빼는 이유는 난이도가 아니라 계약이 흐려지기 때문이다.

## 1. 역할

| 역할 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|
| Owner | 보드 수정·삭제, 멤버 권한 변경, 초대 취소, 컬럼·카드 전부 | 없음 |
| Editor | 컬럼·카드·댓글 작성/수정/이동, 다른 Editor 초대 제안 | 보드 삭제, Owner 강등, 멤버 추방 |
| Viewer | 보드·카드·댓글 조회, 본인 댓글 작성 | 카드 수정, 컬럼 변경, 초대 |

권한은 보드 단위다. 한 사람이 보드 A의 Owner이자 보드 B의 Viewer일 수 있다.

## 2. 화면

1. 로그인 / 회원가입
2. 내 보드 목록. 초대 받은 보드와 내가 만든 보드
3. 보드 상세. 컬럼과 카드
4. 카드 상세. 모달 또는 패널. 설명, 담당, 마감, 태그, 체크리스트, 댓글, 활동 로그
5. 보드 설정. 이름, 멤버, 초대, 컬럼 WIP
6. 받은 초대함
7. 마이페이지. 닉네임, 비밀번호, 알림 설정
8. 검색 결과. 내가 접근 가능한 보드만

랜딩 페이지는 로그인 진입 한 화면으로 대체한다.

## 3. 기능

각 기능의 완료 조건은 QA 시나리오의 원문이다. 구현 세부가 아니다.

### 3.1 계정

- 이메일과 비밀번호로 가입한다. 이메일 형식, 비밀번호 8자 이상, 중복 이메일은 거절한다.
- 로그인 실패와 성공의 메시지는 계정 존재 여부를 드러내지 않는다.
- 로그아웃하면 보호 화면 접근이 거절된다.
- 닉네임, 비밀번호를 변경할 수 있다. 비밀번호 변경은 현재 비밀번호를 요구한다.

### 3.2 보드

- Owner는 보드를 만들고 이름과 색을 바꿀 수 있다.
- 목록은 내가 Owner이거나 멤버인 보드만 보인다.
- Owner만 보드를 삭제한다. 삭제는 확인 단계를 거친다. 삭제된 보드의 카드 URL은 404가 아니라 권한 없음으로 처리한다.
- 보드에는 컬럼 WIP 한도를 둘 수 있다. 한도를 넘기면 카드 생성과 그 컬럼으로의 이동이 거절된다.

### 3.3 초대와 멤버

- Owner와 Editor는 이메일로 초대한다. 역할은 Editor 또는 Viewer만 지정한다. Owner 초대는 없다.
- 이미 멤버이거나 대기 중인 이메일은 다시 초대할 수 없다.
- 수신자는 수락 또는 거절한다. 수락 전에는 보드가 보이지 않는다.
- Owner는 대기 초대를 취소하고, Editor를 Viewer로 바꾸거나 멤버를 내보낼 수 있다.
- 마지막 Owner는 나가거나 강등될 수 없다.

### 3.4 컬럼

- Owner와 Editor는 컬럼을 만들고, 이름과 순서를 바꾸고, 지울 수 있다.
- 카드가 있는 컬럼 삭제는 거절하거나, 카드를 다른 컬럼으로 옮긴 뒤에만 허용한다. v1은 거절한다.
- 기본 컬럼 세 개(할 일, 하는 중, 완료)는 보드 생성 시 만들어 둔다. 지울 수는 있다.

### 3.5 카드

- 카드는 제목, 설명, 담당자, 마감일, 태그, 체크리스트를 가진다. 제목만 필수다.
- 담당자는 그 보드 멤버만 된다.
- 카드는 같은 보드의 다른 컬럼으로 옮긴다. WIP 초과면 거절하고 이유를 보여 준다.
- 같은 컬럼 안에서 순서를 바꾼다.
- Editor는 자신이 만들지 않은 카드도 수정할 수 있다. Viewer는 불가.
- 카드 삭제 권한은 Owner, 또는 그 카드를 만든 Editor다.

### 3.6 의존 관계

- 카드는 같은 보드의 다른 카드 하나를 선행 카드로 지정할 수 있다. 자기 자신과 순환은 거절한다.
- 선행 카드가 완료 컬럼에 없으면 이 카드는 차단 상태로 표시한다.
- 차단된 카드도 완료 컬럼으로 옮길 수는 있다. 막지 않고 경고만 보여 준다. 강제는 다음 버전.

이 기능이 MVP를 넘기는 핵심이다. 권한과 맞물려 상태 규칙이 생긴다.

### 3.7 댓글과 활동 로그

- 멤버는 댓글을 작성한다. 수정·삭제는 작성자와 Owner만.
- 활동 로그는 시스템이 남긴다. 생성, 컬럼 이동, 담당자 변경, 마감 변경, 멤버 변경. 사용자가 로그 문장을 수정하지 못한다.
- 댓글에서 `@닉네임`은 보드 멤버만 멘션으로 인정한다. 없는 닉네임은 일반 텍스트다.

### 3.8 알림

- 알림 종류는 초대 수신, 카드 담당 지정, 멘션, 마감 24시간 전이다.
- 인앱 목록에서 읽고 안 읽음이 구분된다.
- 이메일 발송은 v1에서 하지 않는다. 인앱만.

### 3.9 검색

- 제목, 태그, 담당자 닉네임으로 검색한다.
- 접근 불가 보드의 카드는 결과에 나오지 않는다.
- 빈 검색어는 요청하지 않는다.

## 4. 데이터 계약

구현 컬럼명이 아니다. 엔티티와 관계만 고정한다.

- User 1 — N BoardMember — 1 Board
- Board 1 — N Invitation
- Board 1 — N Column 1 — N Card
- Card N — 1 User (assignee, nullable)
- Card N — 1 Card (predecessor, nullable, 같은 보드)
- Card 1 — N ChecklistItem
- Card 1 — N Comment
- Card 1 — N Activity
- User 1 — N Notification

지울 때: 보드 삭제는 컬럼·카드·초대·멤버십을 함께 지운다. 유저 탈퇴는 v1에서 하지 않는다.

## 5. 공통 실패

모든 쓰기 API는 아래 중 하나로 거절한다.

- 인증 없음
- 보드 멤버 아님
- 역할 부족
- 대상 없음
- 값 검증 실패 (중복 초대, 순환 의존, WIP 초과, 마지막 Owner)
- 충돌. 같은 카드를 두 사람이 수정하면 나중 요청은 버전 불일치로 거절한다. 자동 머지하지 않는다.

낙관적 UI를 쓰더라도 거절되면 화면은 서버 상태로 되돌려야 한다.

## 6. QA가 먼저 쓸 시나리오

1. Viewer가 카드 수정을 호출하면 거절되고 보드는 변하지 않는다.
2. 초대 수락 전에 보드 URL로 들어가면 카드가 보이지 않는다.
3. A → B → A 의존은 거절된다.
4. WIP 2인 컬럼에 세 번째 카드를 옮기면 거절되고 원래 컬럼에 남는다.
5. 마지막 Owner 강등은 거절된다.
6. 검색은 다른 보드의 비멤버 카드를 반환하지 않는다.
7. 오래된 버전으로 카드 제목을 저장하면 거절되고 최신 제목이 유지된다.

## 7. ChatGPT에 넘길 때

한 번에 전체를 늘리지 않는다. 섹션 번호를 지정하고 아래만 요청한다.

- 그 기능의 예외를 3개 더 찾고, 기존 완료 조건과 모순되면 표시
- 화면 필드 목록. 새 기능 추가는 금지
- 거절 메시지의 사용자용 문장

새 엔티티를 제안받으면 이 문서의 4장에 넣을지 사람이 결정한다. 에이전트는 이 초안에 없는 엔티티를 구현 범위로 넣지 않는다.

## 8. 열린 결정

- A. 코드잇 제공 API 소비인가, 자체 API인가. 이 명세는 자체 API를 전제한다. 제공 API만 쓰면 3.6 의존, 3.8 알림, 버전 충돌은 목 서버가 필요하다.
- B. 카드 상세는 모달인가 우측 패널인가. 기능 계약은 같다.
- C. 마감 24시간 알림의 기준 시각. 서버 기준 UTC로 두고 화면만 로컬 타임존으로 보여 주는 안을 기본값으로 둔다.
