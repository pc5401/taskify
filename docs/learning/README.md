# Taskify 개발 흐름 읽기

이 문서는 개발을 처음 배우는 사용자가 “무엇을 만들었고, 무엇을 확인했으며, 무엇이 남았는가”를 이해하도록 돕습니다. 코드를 읽거나 서버를 실행할 필요가 없습니다.

1. [사이클 01: 로그인에서 실제 DB 검증까지](cycle-01.md)를 읽습니다. 역할 표 → 협업 그림 → 인증 그림 → 결함 사례 → 증거 표 순서로 읽으면 됩니다.
2. [사이클 02: 참여한 보드의 내용을 정확하게 읽기](cycle-02.md)에서 조회 권한, 필터·페이지, 계산된 카드 상태와 다음 쓰기 작업을 이어 읽습니다.
3. [사이클 03: 카드를 만들고 옮겨도 데이터가 어긋나지 않게 하기](cycle-03.md)에서 WIP, 버전 조건, 원자성과 검사 도구 검토를 배웁니다.
4. [사이클 04: 담당자를 고르고, 실제 화면에서 확인하기](cycle-04.md)에서 공개 멤버 정보, 선택·저장·필터, 실제 클릭과 디자인 검증 범위를 배웁니다.
5. 더 확인하고 싶은 내용만 각 절의 원자료 링크로 이동합니다. 원자료에는 과거 상태도 남아 있으므로 날짜와 기준 커밋을 함께 봅니다.
6. 다음 작업이 끝나면 [사이클 양식](cycle-template.md)으로 새 설명을 추가합니다. 이전 사이클의 미완료 내용을 지우지 않고 다음 결과와 연결합니다.

| 문서 | 기준 | 읽고 얻는 것 |
|---|---|---|
| [사이클 01](cycle-01.md) | 2026-10-12, 통합 `25ab91f` | 역할 분담, 승인, 로그인 구조, 모의/실제 검증의 차이 |
| [사이클 02](cycle-02.md) | 2026-10-12~13, 조회·권한 배치 | 보드 경계, 정렬·필터·책갈피, 차단·경고 계산, 쓰기 작업 예고 |
| [사이클 03](cycle-03.md) | 2026-10-13, 카드 생성·이동 배치 | 마지막 자리 경쟁, 버전 충돌, no-op·재배치, 원자성, 검사 가정 검토 |
