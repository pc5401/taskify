# Taskify 개발 흐름 읽기

이 문서는 개발을 처음 배우는 사용자가 “무엇을 만들었고, 무엇을 확인했으며, 무엇이 남았는가”를 이해하도록 돕습니다. 코드를 읽거나 서버를 실행할 필요가 없습니다.

1. [사이클 01: 로그인에서 실제 DB 검증까지](cycle-01.md)를 읽습니다. 역할 표 → 협업 그림 → 인증 그림 → 결함 사례 → 증거 표 순서로 읽으면 됩니다.
2. 더 확인하고 싶은 내용만 각 절의 원자료 링크로 이동합니다. 원자료에는 과거 상태도 남아 있으므로 날짜와 기준 커밋을 함께 봅니다.
3. 다음 작업이 끝나면 [사이클 양식](cycle-template.md)으로 새 설명을 추가합니다. 이전 사이클의 미완료 내용을 지우지 않고 다음 결과와 연결합니다.

| 문서 | 기준 | 읽고 얻는 것 |
|---|---|---|
| [사이클 01](cycle-01.md) | 2026-10-12, 통합 `25ab91f` | 역할 분담, 승인, 로그인 구조, 모의/실제 검증의 차이 |
| [재사용 양식](cycle-template.md) | 다음 사이클 작성용 | 사실과 증거 범위를 빠뜨리지 않는 설명 순서 |
| [해설 담당 역할](../../agents/explainer/CHARTER.md) | 이번 사용자 요청 | 작성 범위, 조율 담당의 호출·검토 절차 |

학습 문서는 계약이나 QA 판정을 대신하지 않습니다. 서로 다르게 보이는 내용은 [제품 계약](../contract/v0.2.1.md), 해당 시점의 [QA 결과](../../agents/qa/live/RESULTS.md), [조율 기록](../../agents/shared/orchestration-2026-10-11.md)에서 범위와 시점을 확인합니다.
